# Audit & Activity Logs

## Purpose
The Audit & Activity Logs module provides a production-grade, read-only administrative view into historical system events. It leverages the existing `AuditEvent` infrastructure (populated by `AuditService`) to deliver secure insights into organization operations without altering historical immutability.

## Endpoints
This module extends the canonical organization hierarchy:
- `GET /organizations/current/audit-logs`
  Retrieves a paginated list of audit events.
- `GET /organizations/current/audit-logs/:id`
  Retrieves the full structural JSON payload (metadata) of a single audit event.

## Immutability & Write Safety
This module guarantees **100% read-only boundaries**.
- No `POST`, `PATCH`, or `DELETE` endpoints exist.
- It operates completely independently from the write mechanisms housed in `AuditService`.
- It physically cannot mutate historical archives.

## Filtering & Pagination
Available filters structurally map directly to the `AuditEvent` schema for indexed querying:
- `from` & `to`: ISO timestamps validating strictly against `created_at`.
- `actorId`: The UUID of the user triggering the event.
- `action`: Specific string (e.g., `PROJECT_CREATE`).
- `entityType` & `entityId`: Granular boundaries for auditing specific domain models.

Pagination employs `page` and `limit` boundaries, capped structurally at a maximum of `100` items to prohibit memory exhaustion. Order is rigidly deterministic: primarily newest-first (`created_at: desc`), defaulting secondarily to UUID (`id: desc`) on collision.

## Tenant Isolation
The API actively blocks any direct `organization_id` injection from the client query structure. Tenant context is evaluated forcefully via the generic `@CurrentTenant()` context resolver, ensuring cross-tenant boundaries are strictly maintained. Event detail retrievals explicitly block viewing records generated in unrelated organizations.

## Sensitive Data Handling
Metadata objects generated by Identity/Access routines (like `SESSION_CREATED`) have been inspected and confirmed to omit all `access_tokens`, `refresh_tokens`, and hashed passwords. The read module safely delivers these clean structural archives.

## Permissions
Requires:
- `audit_events:read` (For traversing logs globally inside the tenant boundary).
